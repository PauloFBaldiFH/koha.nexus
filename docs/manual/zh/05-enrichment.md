# 5. 记录补充与 Z39.50/SRU

[目录](README.md)

## 补充现有记录

导入接收外部导出，补充则查找现有记录的附加信息或找到新书。打开 **Library tools > On-demand enrichment**，或按 n；当前菜单不使用旧批量页面。

输入 `all` 或 `101, 102, 500-510` 等 `biblionumbers`，按 **Search**。监视任务与服务器；大任务在后台运行，重启后可继续，但机器须可用。**Pause**/**Resume** 不撤销已应用的修改。

打开报告，对照主题、分类、注释和载体描述。**Search more servers** 查询尚未使用的来源，**Choose donor** 为字段组选来源。只有审查并确认 **Apply** 后才写馆藏；搜索与报告本身不写入。相同题名不足以证明同一版本。

当前界面查询直接 Z39.50。每个服务器有自己的限制，延迟或无结果不证明其他馆没有此书。不存在通用的 50 条搜索上限。应用时，小任务保存记录副本，大任务采用验证过的完整 backup；都不能省略审查。**Revert** 按保护规则恢复旧版记录，并保留应用后又在 Koha 编辑过的记录；它不是整个数据库的 restore。

## 新书与规范记录

同页可按 ISBN 或题名、作者、年份使用 **Find**，检查并选中来源，再确认 **Import as new record**。它新增记录，不按相同 ISBN 自动替换。来源馆的本地 `9XX` 被移除并记录来源，防止把对方馆藏当本馆实物。新增后按本馆规则建立册；相关批次可由 **Undo a MARC import** 处理。

**Enrich & standardize authorities** 或 h 提供精确形式、近似形式。近似形式可能建议拼写校正并建立初步规范记录，需人工核对。流程先查本 Koha，再查补充数据库及直接服务器，优先巴西来源，主题仅查询巴西来源；不能推断符合所有馆的编目政策。

审查报告再 **Apply**，流程有安全 backup，会建立必要规范记录和链接。报告生成后被编辑的记录保留。回退时仍有链接的新规范记录不会被随意删除。

## Z39.50 与 SRU 配置

用 z 或侧栏打开 **Z39.50 / SRU servers**。本 Koha 的入站服务器供别馆查询，开关还影响相应防火墙端口。社区网络配置共享来源，与按需补充直接查询的服务器不同。

健康表的 **Reset**/**Reset all** 允许重试，不能修好远端。用空格选择来源、**Scan** 实际查书，再 **Add to Koha** 添加有效服务器；扫描不是只测端口。配置支持 SRU 不等于所有补充查询都用 SRU，也不必为访问外馆而开放本馆入站服务。

外部来源的可用性、覆盖、访问条件和本馆网络连通性均待当地确认，服务器列表并不保证全部随时可访问。
