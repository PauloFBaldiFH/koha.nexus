# 8. 일정, VPN, 메시지와 관리

[목차](README.md)

## 일정과 cron

작업 전에 현재 상태와 최근 backup을 확인하십시오. s 또는 **Schedules & cron tasks**를 열면 작업별 활성화, 빈도, 시간과 필요한 요일·날짜·사용자 표현식이 있습니다. **Reload**로 현재 값을 읽고 필요한 것만 켠 뒤 `HH:MM`으로 시간을 설정합니다. **Preview**로 파일을 확인하고 **Save**에서 변경 요약을 승인한 다음 다시 읽어 검증합니다.

관리 파일은 `/etc/cron.d/koha_tasks`이고 이전 사본은 `koha_tasks.bak`입니다. 비활성 작업은 시간과 함께 주석으로 남고 손으로 작성한 줄은 보존됩니다. **Defaults**는 기본값을 화면에 채울 뿐 저장하려면 **Save**가 필요합니다.

기본 SQL은 매일 23:00, MARC는 일요일 03:00의 서버 시간입니다. 이미 바꾼 일정과 시간대를 확인하십시오. 그 시간에 컴퓨터와 Linux가 실행 중이어야 하며 Windows가 자동으로 켜진다는 보장은 없습니다. Koha 자체의 통지는 여기서 관리하는 추가 작업과 다른 발송 체계를 가집니다.

## WireGuard VPN

**Security & access hub > WireGuard VPN** 또는 v에서 공용 주소·서버 이름과 UDP 포트를 입력합니다. **Set up the VPN**의 네트워크 변경 확인을 읽으십시오. 라우터가 있으면 해당 UDP 포트를 서버로 전달해야 합니다.

기기마다 이름을 붙여 **Add device**, 선택 후 **QR code & profile**로 WireGuard 클라이언트를 구성합니다. 연결, staff와 표시된 트래픽을 시험하십시오. 프로필과 QR은 비공개입니다. **Revoke**는 해당 설정을 무효화하며 다시 연결하려면 새 프로필이 필요합니다. **Turn off**는 VPN과 연결을 끊지만 확인문에 따라 프로필은 유지합니다.

분할 터널은 `10.66.0.0/24`만 VPN으로 보내며 인터넷과 DNS는 기기의 원래 연결을 사용합니다. 연결 시 staff는 `http://10.66.0.1:8080`입니다. WSL에 mirrored 네트워크가 없으면 직접 도달할 수 없다고 표시하고 이 VPN을 비활성화합니다.

## 메시지와 상호운용

m 또는 **Messaging & interoperability**에는 **E-mail**, **WhatsApp & Telegram**, **SMS**, **Alerts**, **SIP2**, **Z39.50** 탭이 있습니다. 실제 표시는 설치 언어에 따라 번역될 수 있습니다.

메일을 켜고 기본 SMTP를 확인하십시오. 버튼은 SMTP 설정, 도서관 주소, 통지·전표, 연체 규칙을 엽니다. 발송 활성화만으로 모든 수신자·대출 규칙이 채워지는 것은 아닙니다. 서버, 이용자 설정, 통지 템플릿과 제공자 인증 안내를 확인하고 비공개 정보는 공개 기록에 넣지 마십시오.

**Set up WhatsApp and Telegram**은 서비스, 국가·지역 번호, 시험 발송, 통지 활성화와 전화 검사를 제공합니다. WhatsApp은 게이트웨이, Telegram은 bot과 수신자 설정에 의존합니다. 허락된 사람에게 먼저 시험하고 실제 통지를 켭니다. 전화번호 일괄 수정은 미리보기를 읽은 뒤 판단하십시오. SMS는 `SMSSendDriver`와 이용자 메시지 설정뿐 아니라 호환 드라이버·서비스가 필요합니다. 이름 입력만으로 발송이 보장되지 않습니다.

**Alerts**는 반납기한·연체 알림, 반복 간격과 일일 요약을 지원합니다. 채널을 고르고 저장하며 **Dry run (sends nothing)**은 보내지 않고 시험 결과를 보여줍니다. 활성화하면 해당 예약 작업도 켜므로 cron을 확인합니다. Koha 자체 통지와 겹쳐 같은 일을 두 번 알리지 않도록 정책을 정하십시오.

SIP2는 무인대출 기기의 포트, 네트워크, 도서관과 권한을 설정합니다. 예제 제거를 확인하고 버튼으로 필요한 Koha 계정을 만드십시오. 서버와 기기의 계정 설정이 맞아야 합니다. 로컬 시험을 위해 모든 네트워크에 포트를 열지 마십시오. Z39.50 탭은 5장의 서버 화면으로 이어지며 외부 검색과 자관 공개는 다른 방향입니다.

## 보안과 원격 관리

중심에는 Cloudflare Tunnel, UFW, staff 8080 제한, HTTPS와 Fail2ban도 있습니다. 상태와 요약을 읽고 확인하십시오. 터널·VPN·포트 직접 공개는 설정과 도달 범위가 다릅니다. 원격 서버의 방화벽을 바꾸기 전에 이후의 관리 경로를 확보하십시오.

**확인 필요:** 도메인, 라우터, 인터넷 제공자 및 기관의 공개 요건은 코드만으로 알 수 없습니다. 모든 환경에 같은 공개 절차를 적용하지 않습니다.

## 설정, 언어, 업데이트

**Koha settings & parameters**에서 메모리·worker와 시간대를 조정하고 넓은 권한의 관리자를 만들 수 있습니다. 필요한 사람에게만 관리 권한을 주십시오. **Koha languages**는 다운로드와 활성화, 다운로드만 하기, 설치된 언어 활성화, 목록 보기가 구분됩니다. 내려받기만으로 활성화되지는 않으므로 패널·staff·OPAC 결과를 확인합니다.

**Update center**에서는 운영체제 패키지·Koha 구조 업데이트와 GitHub를 통한 패널 업데이트를 구분합니다. backup과 유지보수 시간을 마련하십시오. 새 패널을 다음 실행에 불러오려고 세션이 끝날 수 있습니다. 구조 업데이트 실패는 재시작만으로 해결됐다고 여기지 말고 오류와 진단을 확인합니다.

## 도서관 관리 도구

**Library tools**에는 전거 동기화·연결, 저자 중복 검색, SQL 보고서, 이용자 범주 변경, 품질 검사와 개인정보 작업이 있습니다. 범주 변경은 서로 다른 원본·대상, 선별 조건과 도서관을 고른 뒤 시험 결과와 backup을 확인합니다. 품질 검사는 읽기 전용이며 모든 문제를 자동 수정하지 않습니다.

이력 익명화는 Koha 절차에 따라 오래된 기록과 이용자의 연결을 없애며 모든 서지 이력을 지우지 않습니다. 오래된 이용자 삭제는 필터, 시험, 표시된 수를 이용한 확인이 필요하고 데이터를 지웁니다. 보존 정책을 먼저 확인하십시오. 비슷한 저자 이름이 같은 사람의 증거는 아닙니다. 현재 메뉴에서 숨긴 도구를 사용 가능한 카드로 취급하지 마십시오.
