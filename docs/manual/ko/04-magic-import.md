# 4. 매직 가져오기

[목차](README.md)

## 원본과 시험 자료 준비

**Magic Import Tool**은 서지, 소장자료, 이용자, 전거 데이터를 읽습니다. 형식을 알아냈다고 모든 필드의 해석까지 맞는 것은 아닙니다. 특히 머리글이 없는 표와 로컬 필드를 확인해야 합니다.

원본과 검증된 Koha backup을 보관하십시오. 여러 소장자료, 발음 구별 문자, 빈 필드, 예외를 포함한 대표 표본부터 시험하고 원본 시스템과 미리보기의 수를 비교합니다. 이용자 내보내기는 공개하지 마십시오. i 또는 사이드바에서 도구 카드를 열고 파일이나 폴더를 선택합니다. 경로는 실행 중인 Linux에서 읽을 수 있어야 합니다. 브라우저나 원격 터미널 컴퓨터에만 있는 파일이 서버로 자동 전송되지는 않습니다.

## 지원 형식과 한계

MARC21 ISO 2709, MARCXML, 텍스트 MARC와 MarcEdit `.mrk`를 인식합니다. `.mrk`라는 이유만으로 변환할 필요는 없습니다. CSV/TSV, Excel XLSX/XLS, LibreOffice ODS, dBase DBF에서는 구분자, 머리글, 자료형, 실제 감지값을 확인합니다. 표 형태의 JSON/XML도 읽지만 임의의 XML이 MARCXML인 것은 아닙니다.

머리글 없는 조각을 포함한 인식 가능한 SQL에서는 데이터와 관계를 추출합니다. SQL 파일을 이전용 프로그램으로 실행하지 않습니다. 표 사이의 모호한 연결을 점검하십시오.

ISIS 전용 읽기 기능은 `acervo` 테이블이 있는 인식 가능한 PostgreSQL 내보내기를 처리합니다. CDS/ISIS `.mst` 마스터 파일은 직접 읽지 않으므로 WinISIS에서 ISO 2709로 내보냅니다. Biblioteca Fácil은 관련 테이블을 함께 유지한 인식 가능한 사본이나 데이터 폴더를 사용합니다. 서지, 이용자, 대출, 예약을 각각 확인하십시오.

전체 Koha backup은 데이터베이스 교체인 restore로 안내됩니다. 다른 시스템의 PostgreSQL, 특히 바이너리 pg_dump는 MariaDB에 바로 복구할 데이터베이스가 아닙니다. 읽을 수 없다고 나오면 원본에서 MARC나 표로 내보내십시오. 압축 묶음은 각 구성 파일의 판정 결과를 읽습니다. PDF, 사진, 일반 문서, 실행 파일은 이 읽기 기능의 서지 내보내기로 사용할 수 없습니다.

## 수동 필드 매핑

화면 위의 **Bibliographic**, **Patrons**, **Authorities**를 확인하고 잘못 분류되었으면 선택기로 수정합니다. 표본의 필드를 선택해 목적 필드와 기능을 검토합니다. 유지, 다른 필드로 보내기, 고정 텍스트, 제외를 구분하십시오. 식별자를 버리기 전에 다른 테이블과의 관계를 확인합니다.

구분선이나 Ctrl+Up/Ctrl+Down으로 표의 높이를 조절할 수 있습니다. **Values of this Koha**에서 유효한 도서관, 자료 유형, 이용자 범주 코드와 기본값, 원본에서 대상 값으로의 매핑을 점검합니다. 코드가 기본값과 다르다는 것만으로 무효는 아닙니다.

**Record preview**는 결과 표본을 보여줍니다. **Check the whole file**은 전체 파일을 준비·검증하며 이 단계에서는 Koha에 가져오지 않습니다. 매핑을 재사용하려면 프로필 이름을 넣고 **Save**, 저장된 것을 선택해 **Use**를 누릅니다. 내보내기 구조가 바뀌면 다시 검토하십시오.

**Apply** 또는 Ctrl+S는 매핑을 받아들이고 준비를 계속하는 것으로, 최종 등록 확인이 아닙니다. Esc를 포함한 **Skip: import as it is**는 수동 매핑을 건너뛰며 전체 절차를 취소하지 않습니다. 중복 묶기나 일괄 글자 변경은 미리보기로 확인하여 약어, 고유명, 소장자료 코드를 훼손하지 않도록 합니다.

## 소장자료 정규화

Koha의 기존 `952`는 유지하고, 요청했을 때 유효한 대상 코드로 도서관·유형을 다시 매핑할 수 있습니다. `949`, `852`, `950`, `990`은 시스템별로 의미가 다릅니다. Pergamum과 Biblivre에서도 하위 필드를 직접 확인해야 합니다. 바코드, 소유·소재 도서관, 청구기호, 유형, 위치, 입수일을 점검하십시오.

숫자와 `DL`, 날짜로 된 법정 납본 주석만으로 자관 소장자료를 만들어서는 안 됩니다. 실제 자료의 독립적인 증거가 있는지 확인하고 제외되거나 애매한 항목을 검토합니다.

바코드가 없으면 기본 정책은 검토입니다. 대체 식별자 생성은 해당 선택과 안정적인 이전·출처 식별을 요구하며, 이미 있는 바코드와 충돌한다고 몰래 번호를 바꾸지 않습니다. 누락, 중복, 대상과의 충돌을 먼저 확인하십시오. SQL의 서지와 소장자료 관계를 열 위치나 행 순서만으로 추정하지 마십시오.

## 이용자와 전거

**Patrons**에서는 이름·성, 카드 번호, 연락처, 주소, 생년월일·등록일·만료일, 도서관·범주를 각각 확인합니다. CPF, 이메일, 날짜 형태는 단서이지 정확한 분류의 증명이 아닙니다. 같은 형식의 날짜도 용도가 다릅니다. 기본 범주는 대상 Koha에 존재해야 합니다.

기존 이용자를 카드 번호로 맞춰 업데이트할 것인지 묻는 선택을 읽으십시오. 기존 자료 갱신과 새 이용자만 추가는 다릅니다. 추측으로 관리 권한이나 인증 필드를 지정하지 마십시오.

**Authorities**에서는 식별자, 채택 표목, 이형, 관계와 전거 유형을 확인합니다. 모드 변경은 원본에 없는 정보를 만들어내지 않습니다.

## 등록과 사후 점검

출력 준비 후 미리보기, 수, 거부, 경고와 도서관·유형·범주·이용자 갱신 질문을 읽은 뒤 데이터베이스 쓰기를 승인합니다. 기존 서지를 유지하고 새 소장자료만 추가할지, 서지를 교체할지, 비교 없이 모든 행을 새 서지로 만들지 구분하십시오. 같은 묶음을 실수로 되풀이하지 마십시오.

후속 단계 실패가 앞 단계의 취소를 보장하지 않습니다. 서지·전거·이용자·대출 단계가 일부 반영되었을 수 있습니다. 요약과 로그를 보관하고 수를 확인한 뒤 재실행을 판단합니다. Koha에서 표본, 소장자료, 이용자와 전거 연결을 점검하십시오. **Library tools > Undo a MARC import**는 MARC 묶음용이며 이용자·대출·예약의 만능 취소가 아닙니다.

**확인 필요:** 특정 제품 버전이나 독자적인 내보내기 구조는 표본과 결과 검토가 있어야 호환성을 판단할 수 있습니다. 형식 이름을 인식한다는 것만으로 모든 변형을 보장하지 않습니다.
