# 3. Backup과 restore

[목차](README.md)

## 하나의 Backup center에서 작업 구분하기

기본 화면에서 b 또는 사이드바의 **Backup center**를 여십시오. 최신 파일, 크기, 야간 결과, 압축 선택과 작업 카드가 모여 있습니다.

| 카드 | 용도 |
| --- | --- |
| Download latest backup | 이미 존재하는 최신 파일을 컴퓨터로 전송 |
| Generate manual backup and download to PC | 현재 데이터베이스의 사본을 생성·검사한 뒤 전송 제공 |
| Export MARC21 records now | 서지와 전거 레코드 내보내기 |
| Restore database | 선택한 파일로 현재 데이터베이스 교체 |
| Configure cloud backup | 외부 서비스로 보내도록 설정 |
| Test integrity of latest backup | 임시 데이터베이스로 가져와 검사 |

**Restore database는 이 센터의 카드입니다.** 상단의 별도 restore 버튼이나 기본 메뉴의 다른 진입점을 찾지 마십시오. 마지막 야간 실행 결과와 최신 파일의 날짜·크기는 서로 다른 실행일 수 있습니다.

SQL backup은 Koha 데이터베이스이며 Windows, Debian 전체 또는 컴퓨터의 디스크 이미지가 아닙니다. MARC21 내보내기는 서지·전거 파일을 `.tar.gz`에 묶습니다. 이용자와 대출을 포함한 완전한 복구에는 SQL이 필요합니다.

자동 SQL과 안전 사본은 기본적으로 `/var/backups/koha_sql`, MARC는 `/var/backups/koha_marc`에 있습니다. 수동 저장은 화면에서 별도 경로를 고르며 기본 제안은 감지된 홈 폴더의 `backups`입니다. 큰 파일은 `.part`로 쓰다가 검사 후 최종 이름으로 바뀝니다. `.part`를 완성된 backup으로 선택하지 마십시오.

## 압축 선택

**Compression**의 gz는 호환성, zst는 속도와 큰 목록, xz는 작은 파일 크기에 적합하도록 설명되어 있습니다. 선택 즉시 저장되며 새 야간·수동·안전 사본에 적용되고 기존 파일을 다시 압축하지 않습니다. 필요한 프로그램을 설치하지 못하면 문제가 표시되고 새 파일은 gzip으로 계속될 수 있습니다. 실제 사용 형식의 안내를 읽으십시오.

restore는 현재 선택과 관계없이 지원되는 `.sql`, `.sql.gz`, `.sql.zst`, `.sql.xz`를 읽습니다. 확장자가 올바르다는 사실만으로 파일 내용까지 유효한 것은 아닙니다.

## 수동 생성과 컴퓨터로 전송

수동 카드에서 서버의 쓰기 가능한 폴더를 확인하고 **Save backup**을 누릅니다. 생성·검사가 끝날 때까지 기다리십시오. 저장하거나 복사하는 동안은 화면을 닫을 수 없습니다. 결과의 이름, 크기, 경로를 확인합니다.

WSL에서는 **Save to Windows Downloads** 또는 **Choose folder in Windows**로 외부 사본을 만듭니다. 원격 연결에서는 표시된 전송 명령을 자신의 컴퓨터 터미널에서 실행합니다. WSL용 폴더 버튼은 WSL에서만 나옵니다. 다른 설치의 예제 명령을 복사하지 말고 현재 환경이 만든 명령을 쓰십시오. 파일 도착을 확인한 뒤 **Finish and exit**로 끝냅니다.

다른 backup이나 restore가 실행 중이라는 공유 잠금 안내가 있으면 기다립니다. 외부에서 경쟁 작업을 시작해 잠금을 우회하지 마십시오. **Download latest backup**은 기존 파일의 다운로드일 뿐 새 사본을 만들지 않습니다. 중요한 변경 직전의 파일이 필요하면 수동으로 생성하십시오.

## 무결성 검사와 MARC 내보내기

검사 카드에서 제안된 파일·날짜를 읽고 필요하면 **Choose another file**을 선택합니다. 동의하면 임시 데이터베이스에 가져와 테이블, 서지, 이용자 수 등을 검사합니다. 운영 데이터베이스를 교체하지 않습니다. 성공은 그 환경에서 시험한 해당 파일에만 적용됩니다. 같은 파일의 외부 전송과 보관도 끝내십시오.

MARC 내보내기는 확인 후 실행하고 묶음의 경로·내용을 읽습니다. Koha는 계속 운영할 수 있습니다. 로컬 다운로드나 원격 전송으로 사본을 보관하고, 클라우드를 사용한다면 업로드 결과도 따로 확인합니다. MARC 교환 파일은 SQL 전체 복구를 대체하지 않습니다.

## 클라우드와 일정

**Configure cloud backup**은 Google Drive의 두 간편 경로와 OneDrive, MEGA, S3 등의 다른 서비스를 제공합니다. 서버 자체에서 승인할지 다른 컴퓨터에서 승인할지에 맞춰 경로를 선택하고 현재 설치의 주소·지시만 따르십시오. S3는 서비스, region 또는 endpoint, bucket을 구분해 확인합니다.

실제 업로드 시험 결과를 읽고 실패를 해결한 다음 목적지에 사본이 도착했는지 확인하십시오. 비공개 승인 정보는 설치 환경의 입력란에서만 다루고 공개 문서·화면에 적지 마십시오. 기본 일정은 서버 시간으로 매일 23:00 SQL, 일요일 03:00 MARC입니다. 변경된 cron과 다를 수 있으며 서버와 Linux가 실행 중이어야 합니다.

## 데이터베이스 restore

**이 작업의 승인은 현재 데이터베이스 교체를 허용합니다.** 유지보수 시간을 정하고 서버 밖에 안전한 사본을 보관하십시오. 이는 운영상 권고이며 패널이 자동으로 외부 전송을 마치는 단계가 아닙니다.

카드에서 대상 파일을 고르십시오. 다른 컴퓨터에 있다면 안내에 따라 서버로 전송합니다. WSL은 Windows 파일을 Linux 저장소로 먼저 복사할 수 있습니다. 읽기 가능 여부, 내용, 무결성, 공간 검사를 보고 의심스럽거나 불완전한 파일 경고를 조사하십시오. 마지막 교체 확인 전까지는 물러날 수 있지만 승인 후에는 패널에서 취소할 수 없습니다.

먼저 임시 데이터베이스에 가져와 필수 테이블과 수를 확인합니다. 실패하면 현재 목록 교체 전에 중단됩니다. 현재 데이터베이스에 테이블이 있으면 `pre_restore_safety_backup_`로 시작하는 사본을 만들고 검증합니다. 실패하면 기존 데이터를 지우기 전에 멈춰야 하며, 빈 데이터베이스는 이 단계를 생략할 수 있습니다.

그 다음 데이터베이스 클라이언트 중지, 재생성·가져오기, 구조 업데이트, 검색 동기화, 색인 재구축, 서비스 재시작이 이어집니다. 저장된 테마가 있으면 OPAC과 staff 화면을 다시 적용하려고 시도합니다.

실패 단계에 따라 의미가 다릅니다. 임시 검사·안전 사본 실패와 교체 이후 실패를 구분하십시오. 일부 생성·가져오기·구조 오류는 이전 상태의 복구를 시도하지만 rollback도 실패할 수 있어 자동 복귀가 보장되지 않습니다. 색인 오류는 데이터베이스 교체 후일 수 있으며 이전 내용이 돌아왔다는 뜻이 아닙니다.

`/var/log/koha-easy-install/restore.log`, `/var/log/koha-easy-install/restore-import.log`, `/var/log/koha-easy-install/zebra-rebuild.log`를 확인하십시오. 상태가 불명확하면 무조건 반복하지 말고 지원을 받아 올바른 파일을 선택합니다. 끝난 뒤 대시보드, staff, OPAC, 레코드, 검색을 확인합니다. SQL 밖의 파일까지 복구되었다고 판단하지 마십시오.
