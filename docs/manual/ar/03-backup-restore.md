# 3. Backup وrestore

[المحتويات](README.md)

## المركز وأنواع النسخ

**Backup center** أو `b`: تاريخ وحجم ونتيجة و**Compression** وبطاقات.

| البطاقة | الهدف |
| --- | --- |
| Download latest backup | نسخ أحدث ملف موجود |
| Generate manual backup and download to PC | إنشاء القاعدة وفحصها ونقلها |
| Export MARC21 records now | ببليوغرافيا وتسجيلات استنادية |
| Restore database | استبدال القاعدة الحالية |
| Configure cloud backup | إرسال خارجي |
| Test integrity of latest backup | اختبار استيراد مؤقت |

**Restore database بطاقة** وليست زراً علوياً أو مدخلاً رئيسياً مستقلاً. النتيجة تخص آخر تشغيل ليلي، والتاريخ والحجم أحدث ملف؛ قد يختلف التشغيل.

يحتوي SQL قاعدة Koha لا صورة Windows/Debian كاملة. يحتوي MARC21 الببليوغرافيا والاستناد في `.tar.gz`، ولا يحل محل SQL للقراء والإعارة. قبل restore لقاعدة فيها جداول تنشأ نسخة أمان متحققة؛ الفارغة قد تتجاوزها.

SQL الآلي والأمان `/var/backups/koha_sql`، وMARC `/var/backups/koha_marc`. اليدوي له هدف منفصل، عادة `backups` داخل المجلد الشخصي المكتشف. يبقى `.part` مؤقتاً إلى الفحص وإعادة التسمية.

## الضغط والنقل

**Compression**: gzip `.sql.gz` واسع التوافق، Zstandard `.sql.zst` سريع وأصغر للكبير، XZ/LZMA `.sql.xz` الأصغر والأبطأ. يحفظ الاختيار فوراً دون زر إضافي للجديد الليلي واليدوي والأمان، لا يعيد ضغط القديم. عند غياب البرنامج أو فشل تركيبه اقرأ الصيغة الفعلية؛ قد يستخدم gzip. يتعرف restore مستقلاً على `.sql/.sql.gz/.sql.zst/.sql.xz`؛ الامتداد لا يثبت المحتوى.

**Generate manual backup and download to PC**: مجلد خادم قابل للكتابة ثم **Save backup** وانتظار الإنشاء والفحص؛ لا تغلق الشاشة أثناء الكتابة والنسخ. تحقق من الاسم والحجم والمسار. في WSL **Save to Windows Downloads/Choose folder in Windows**؛ عن بعد شغل أمر النقل المعروض على جهازك. افحص الاستلام ثم **Finish and exit**.

أزرار Windows فقط مع WSL. لا تستخدم أمر تثبيت آخر لأنه يعتمد على الملف والخادم. انتظر أي backup/restore آخر ولا تتجاوز القفل المشترك بمهمة خارجية متزامنة. **Download latest backup** يجلب الموجود ولا ينشئ؛ Linux المكتبي/WSL يجرب Downloads وSSH قد يعرض أمراً محلياً. إن لا ملف فأنشئ يدوياً.

## الاختبار وMARC والسحابة

**Test integrity of latest backup**: ملف وتاريخ، **Choose another file**، موافقة ثم استيراد مؤقت. النجاح يذكر الجداول والتسجيلات والقراء دون تغيير الإنتاج. يخص الملف والبيئة نفسيهما؛ أبق الوصول إلى النسخة المنقولة نفسها.

**Export MARC21 records now** موافقة وحزمة، فحص مسار ومحتوى ونقل. يستمر Koha؛ السحابة المهيأة تبلغ عن الإرسال. احتفظ بـSQL للقاعدة الكاملة.

**Configure cloud backup**: مساران Google Drive وكذلك OneDrive/MEGA/S3. تفويض بالخادم أو جهاز آخر وفق المعروض فقط. يميز S3 الخدمة والمنطقة/endpoint وbucket. انتظر اختبار الإرسال الحقيقي والاستلام؛ لا تعتمد إعداداً فاشلاً. البيانات الخاصة في التثبيت فقط، لا وثائق وصور عامة أو دعم؛ ملفات حفظها غير مذكورة. SQL يومي 23:00 وMARC الأحد 03:00 بتوقيت الخادم افتراضياً؛ قد يعدل cron ذلك.

## Restore مدمر

**الموافقة تجيز استبدال القاعدة الحالية.** خطط للصيانة ونسخة خارجية؛ لا تنجز اللوحة هذه النصيحة الإضافية تلقائياً عنك.

**Restore database** مع ملف يبلغه الخادم ونقل عند الحاجة. قد ينسخ WSL من Windows إلى Linux أولاً. اقرأ الوصول والمحتوى والسلامة والمكان، وافحص الملف المشبوه أو الناقص رغم امتداده. تحقق ثانية عند الموافقة؛ قبلها يمكن التراجع، بعدها الانتظار بلا إغلاق ولا إلغاء.

أولاً استيراد SQL مؤقت وفحص الجداول الأساسية وعددها؛ الفشل يوقف قبل الاستبدال. تحمى الجداول الحالية بنسخة SQL متحققة `pre_restore_safety_backup_` مع تاريخ ووقت وضغط. فشل النسخ لا ينبغي أن يحذف القاعدة؛ الفارغة قد تتجاوز.

ثم وقف العملاء وإنشاء واستيراد وتحديث المخطط ومزامنة البحث وبناء الفهارس والخدمات. تجرب إعادة المظهر المحفوظ إن توفر. فشل الاختبار أو النسخ ليس دليلاً على الاستبدال. يمكن محاولة العودة حسب مرحلة الإنشاء/الاستيراد/المخطط والنسخة، **لكن rollback قد يفشل أيضاً**. قد يفشل الفهرس بعد restore للقاعدة بلا عودة الكتالوج القديم.

احفظ الرسالة كاملة و`/var/log/koha-easy-install/restore.log` و`/var/log/koha-easy-install/restore-import.log` وللفهرس `/var/log/koha-easy-install/zebra-rebuild.log`. استخدم بطاقة المركز لا الأرقام القديمة، واطلب تقنياً عند الشك. تحقق من dashboard والتسجيلات والبحث OPAC/staff. انتهاء SQL لا يثبت الملفات الخارجية.
