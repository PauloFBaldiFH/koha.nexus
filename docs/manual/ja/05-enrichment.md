# 5. レコードの補完と Z39.50/SRU

[目次](README.md)

## 既存レコードを補完する

取り込みと補完は目的が違います。**Library tools > Enrich from world catalogues**、または n で開きます。旧来の一括補完画面は現在の入口ではありません。`all` か `101, 102, 500-510` のような `biblionumbers` を指定し **Search** を実行します。

大きな処理は背景で動き、再起動後に続行できますが、マシンが稼働している必要があります。**Pause**／**Resume** は検索を制御し、適用済みの変更を戻しません。報告で件名、分類、注記、形態事項を既存値と比較し、**Search more servers** で未検索の相手、**Choose donor** で項目群の出典を選びます。**Apply** の確認までは提案を目録へ書き込みません。

現在の画面は直接 Z39.50 を使います。相手側の制限や停止があり、遅延や結果なしが「他館にない」証拠ではありません。一般的な 50 件制限はありません。小規模の適用はレコードコピー、大規模では検証済み全体 backup で保護しますが、レビューは必要です。

**Revert** は処理の保護規則に沿って旧版を戻し、適用後に編集されたレコードを保全します。全データベースの restore や他人の全編集取り消しではありません。

## 新規書誌と典拠

同じ画面で ISBN、または書名と著者・年を入力し **Find**。出典を見て **Import as new record** を確認すると新規登録され、同じ ISBN の既存レコードを置換しません。相手館のローカル `9XX` は削除し、出典を記録します。自館の現物は別途作成します。関連 MARC バッチは **Undo a MARC import** で扱います。

**Enrich & standardize authorities** または h では完全一致と近似形を選びます。近似は綴り修正や暫定典拠を提案する場合があり、確認が必要です。自館典拠、補完用データベース、直接サーバーの順に検索し、ブラジルの出典を優先、件名はブラジルの出典に制限します。自館の目録方針に適合する保証ではありません。

報告後 **Apply** で安全 backup、必要典拠の作成とリンクを行います。報告準備後の編集は保全し、戻す際もリンクの残る新典拠は保持します。

## サーバー設定

z または **Z39.50 / SRU servers** では通信の向きを区別します。自館サーバーは他館からの検索用で、開閉は対応するファイアウォールにも影響します。共同ネットワークの共有出典と補完用の直接サーバーは別です。

健康表の **Reset**／**Reset all** は再試行を許すだけで相手を修復しません。Space で選択し **Scan** で実検索、動いたものを **Add to Koha**。単なるポート接続試験ではありません。SRU 設定があるから全補完が SRU というわけではなく、外部検索のため自館受信サービスを公開する必要もありません。

各出典の可用性、範囲、条件、自館回線からの到達性は利用時に要確認です。
