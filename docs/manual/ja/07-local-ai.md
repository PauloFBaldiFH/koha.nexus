# 7. ローカル AI

[目次](README.md)

## 提供元と負荷

a で **AI** を開きます。提供元、Ollama、MARC Replace、staff ホームの助手をまとめていますが、一つの設定だけで全ツールが導入されるわけではありません。CPU と RAM を多く使い、Koha を遅くする可能性があります。

**Ollama on this server** の **Check Ollama**、必要なら **Install Ollama**、選択して **Download** を使います。ネットワークとディスク容量が必要です。**Local Ollama** と標準 `http://127.0.0.1:11434` を確認し、**Use for chat**／**Use for cataloguing** で用途を決めます。写真には視覚対応が必要で、文字専用では読めません。

**Test connection** または F5 で接続確認、**Save** または Ctrl+S で保存します。入力しただけでは保存されません。会話欄が空なら構成に従い視覚用選択を使います。**Load models** の内蔵代替リストは実際に設置済みという証拠ではありません。

ダウンロードはディスク、回答用ロードは RAM を使います。**Free memory** は RAM から外し、ダウンロードを消しません。次の要求で再ロードされます。別の提供元でも Ollama 欄は出るので、保存された提供元と URL を確かめ、ローカル導入済みというだけで通信先を推測しないでください。

## 一件の置換と写真からの草稿

ツールを導入・更新してコンパイル結果と staff のリンクを確認し **MARC Replace** を開きます。`.mrc`、`.xml` または貼り付けたレコードに、置換対象の `biblionumber` を指定します。空欄は新規作成の経路なので重複に注意します。**Preview** で現行値と提案を比較してから確定します。

既存所蔵は保全し、入力の所蔵フィールドは除きます。以前の版を MARCXML で保存し、同じ `biblionumber` に提出して戻す案内がありますが、完全 backup の代わりではありません。

**AI cataloguing** は JPEG、PNG、WebP の表紙、標題紙、裏面を最低一枚使います。新規のフレームワークか置換対象を選び、**Read the photos**。草稿の書名、責任表示、出版、ISBN、分類、欠落を写真と照合し、MARC を直してから登録します。チェック桁が正しくても版が一致するとは限りません。分類は採用表で見直し、草稿から所蔵は保存しません。

## 助手と情報保護

**Install, update or remove the assistant** は staff のホームニュース位置を使い、OPAC ニュースには影響しません。Koha 検索と定義済みの読み取り問い合わせを使い、任意生成 SQL を自由実行しません。

提案は未実行です。対象、前後の値、影響を確認して **Approve & Execute** を使います。職員権限を尊重し、その後レコードが変われば再提案が必要な場合があります。会話の消去や助手削除は確定済み変更を戻しません。削除時は会話を消し、確認済み変更の記録を保持します。

負荷を監視し、遅いからと大きな要求を重複させないでください。機器ごとの RAM、ディスク、応答時間は要確認です。遠隔提供元は送信内容を受け取ります。利用者実データで試さず、方針と費用条件を確認します。画面の費用表示は無料の保証ではありません。
