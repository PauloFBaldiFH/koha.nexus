# 2. শুরু করা ও প্যানেল

[সূচিপত্র](README.md)

## প্যানেল খোলা ও চলাচল

প্রস্তুত Debian বা Ubuntu-তে:

```bash
sudo config.sh
```

Windows-এ **Koha** আইকন বা MSIX অ্যাপ খুলুন। প্রথমে ভাষা চাইতে পারে। Textual প্রস্তুত না হলে পুরোনো প্যানেল দেওয়া হতে পারে; আগের মেনুর সংখ্যা দিয়ে বর্তমান কার্ড খুঁজবেন না।

তীরচিহ্নের কী দিয়ে পাশের তালিকায় নির্বাচন করে Enter বা ক্লিক করুন। শুধু নির্বাচন সরালে কাজ চলে না। সঠিক কার্ড খুলে প্রশ্ন পড়ুন। Tab নিয়ন্ত্রণগুলির মধ্যে যায়। মূল পর্দার অক্ষর-শর্টকাট ব্যবহারের আগে লেখার ঘর থেকে বেরোন।

| কী | মূল পর্দার কাজ |
| --- | --- |
| d | Control Dashboard খোলা |
| b | Backup center খোলা |
| c | Debian টার্মিনাল খোলা |
| Ctrl+B | পাশের তালিকা দেখানো বা লুকানো |
| q | প্যানেল থেকে বেরোনো |

নিষ্ক্রিয় প্যানেল থেকে বেরোনো সার্ভার বন্ধ করা নয়। কাজ চললে সংশ্লিষ্ট পর্দার বাতিলের নিয়ম মানুন। ইনস্টল ও restore-এর কিছু ধাপ বাতিলযোগ্য নয়; জানালা বন্ধ করে নিরাপদে থামানো যায় না।

## অবস্থা বোঝা

**Control Dashboard**-এ Koha, ব্যবহারযোগ্য RAM, খালি ডিস্ক, নতুন backup-এর তারিখ/আকার এবং স্থানীয়, LAN ও বিন্যস্ত ইন্টারনেট ঠিকানা থাকে। MariaDB, Apache, RabbitMQ, Memcached, Koha ও HTTP পরীক্ষা সমস্যা বুঝতে সাহায্য করে, কিন্তু পুরো গ্রন্থাগার কার্যক্রমের পরীক্ষা নয়।

নতুন ফাইলের তথ্য এবং শেষ রাতের কাজের ফল আলাদা চলার হতে পারে। নতুন ফাইল থাকলেও রাতের কাজ ব্যর্থ হতে পারে। HTTP উত্তর পাওয়া ওয়েব ইনস্টল শেষ হওয়ার প্রমাণ নয়। **Refresh** আবার পড়ে, **Restart Koha** সার্ভিস মেরামত/পুনরারম্ভ চায়, **Export diagnostics** তথ্য বের করে। পুরোনো ইনস্টলার সমর্থন না করলে বোতাম নাও থাকতে পারে। পুনরারম্ভের আগে চলমান ব্যবহার বিবেচনা করুন।

নিজ সার্ভারে OPAC সাধারণত `http://localhost/`, staff `http://localhost:8080/`। অন্য কম্পিউটারে localhost সেই কম্পিউটার, সার্ভার নয়। প্যানেলের নেটওয়ার্ক ঠিকানা নিন। WSL-এর NAT-এর জন্য LAN অগম্য বলা হলে Windows-এর নেটওয়ার্ক প্রস্তুতি যাচাই করুন। ঠিকানার কার্ডে খোলা বা URL কপি করা যায়।

## কাজ শুরুর প্রস্তুতি

staff-এ Koha-এর ওয়েব ইনস্টলার দেখালে আগে শেষ করুন; সংস্করণভেদে ধাপ বদলাতে পারে। পরে **Koha settings & parameters > Create super librarian** আলাদা অ্যাকাউন্ট তৈরির পথ দেয়। ব্যক্তিগত তথ্য শুধু নিজ সিস্টেমে দিন, বিস্তৃত অধিকার সীমিত রাখুন।

অবস্থা আবার পড়ে OPAC, staff ও অনুসন্ধান পরীক্ষা করুন। backup তৈরি ও পরীক্ষা করুন। সার্ভারের বাইরের কপি কোথায়, কে তা ফিরিয়ে আনবেন ঠিক করুন। বাইরের ব্যবহারযোগ্য কপি নির্ভর করে প্রকৃত স্থানান্তর ও যাচাইয়ের উপর; ড্যাশবোর্ড একা নিশ্চয়তা দেয় না।
